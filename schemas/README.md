# Schemas

Canonical owner of contracts shared between Python, TypeScript, and Rust.

Document model contracts (version `0.1.0`, frozen by M1):

- `common/` — shared ID types, provenance, origin, resources, issues, geometry
- `physical-document/` — what the PDF objectively contains
- `evidence/` — unified third-party parser candidates (region, table, formula, structure, metadata)
- `layout-document/` — visual regions, bands, columns, groups, reading flow
- `semantic-document/` — logical structure of the paper (`RichText` with `TextNodeContent` alias)
- `mapping/` — bindings across layers (physical-layout, source-semantic, render)
- `api/` — OpenAPI HTTP contracts, when they exist
- `fixtures/` — schema validation fixtures (generated by `scripts/build_fixtures.py`)

Do not maintain independent authoritative models in language packages.

HTTP OpenAPI documents are not present yet. `just schema` reports that explicitly until `schemas/api/` contains a spec.

Generated language bindings must come from these schemas through `scripts/generate.py` (registered via `just generate`), must not be edited by hand, and must have a freshness check (`just generate-check`). Current generators: TypeScript types and Python Pydantic models.

Fixture documents under `schemas/fixtures/<name>/*.valid.json` validate against `schemas/<name>/schema.json` in `just schema`.
