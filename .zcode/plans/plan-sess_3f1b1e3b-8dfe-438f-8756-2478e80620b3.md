# M2 Walking Skeleton 实施计划

## 目标

完成 Roadmap M2 全部 7 个 Phase，建立第一条端到端闭环：
`PDF → PhysicalDocument → LayoutDocument → SemanticDocument → Dummy Translation → LaTeX → Target PDF → 双向跳转 Viewer`。故意不追求解析质量，验证架构真实成立。

**已确认决策**：一次性完成全部 7 个 Phase；Phase 2.1 验证用 3 篇真实公开论文 PDF（arXiv 上 CC-BY 许可论文，避免版权问题，作为 Tier-4 external fixture 不提交 PDF 本体，只提交验证脚本与记录）；Viewer 用 apps/web + PDF.js。

## 总体技术选型

- **实现语言**：全部放在 Python（`packages/python/pdf-pipeline`、`packages/python/llm`）。依据 `proposed/architecture/2026-09-03-python-rust-performance-boundary.md`：无 benchmark 证据前不动 Rust。
- **PDFium 接入**：`pypdfium2`（PDFium 的 Python 绑定）。新增依赖到 `pdf-pipeline/pyproject.toml`，通过 uv workspace 安装。
- **契约消费**：直接使用 M1 的 `document-model`（Pydantic 生成模型 + `ids.py`/`validators.py`），所有产物用 schema 校验 + `validate_layer_separation` + `validate_bundle_references` 验证。
- **前置 Agent Note**：`layout-reconstruction-pipeline` note 要求「不悄悄加入原生 PDF 库」——落地一条 implemented note 记录 PDFium/pypdfium2 选型（含许可证说明：PDFium 是 BSD-style，pypdfium2 是 Apache-2.0/BSD，兼容仓库许可）。

## Phase 2.1 — Minimal PDF Backend（`packages/python/pdf-pipeline`）

新建 `src/pdf_pipeline/physical.py`：

- 打开 PDF → 逐页提取：页面尺寸（pt，PDF 坐标系转 schema 约定）、`TextSpan`（PDFium textpage 的 rect + text，合并相邻 fragments）、`ImageObject`（位图与 bbox）、页面渲染（rasterize 供 Viewer 用）。
- 输出符合 `schemas/physical-document` 的 `PhysicalDocument`，通过 document-model 校验。
- 确定性：同一 PDF 字节多次解析产出相同 ID 与内容（Roadmap 1.2 明确此要求属于本 Phase；ID 用确定性派生，如基于文档 id + 页码 + 序号的稳定生成，不随机）。
- **Validation（3 篇真实论文）**：写 `scripts/validate_physical.py` + 手动选取 3 篇 CC-BY arXiv 论文，断言页数、文本完整性（含预期关键词）、坐标在页面范围内。论文 PDF 放 `tests/fixtures/external/`（gitignore，不提交），元数据 yaml 提交。同时在 Tier-1 合成夹具（smoke、two-column）上做确定性 golden 回归。

## Phase 2.2 — Minimal Layout（`packages/python/pdf-pipeline`）

新建 `src/pdf_pipeline/layout.py`：

- 仅支持 `TextRegion`（含 Heading-like：按字号/字体粗体启发式）、`FigureRegion`（ImageObject 聚类）。不做复杂 fusion。
- 可选简单 Evidence 输入（EvidenceBundle candidate），M2 先用自产启发式 candidate，预留 adapter 接口。
- 双栏检测：x 中线 + span x 分布的简单切分；产出 `bands/columns/readingFlow`（ReadingFlowGraph 为真源，primaryFlow 派生）。
- 输出符合 `schemas/layout-document` 的 `LayoutDocument`，跨层校验通过。

## Phase 2.3 — Minimal Semantic Recovery

新建 `src/pdf_pipeline/semantic.py`：

- 仅支持 `Heading / Paragraph / Figure / FigureCaption` 四种 SemanticNode；caption 启发式：FigureRegion 下方紧邻的短文本 span。
- 建立 SemanticNode → LayoutRegion → Physical span 的绑定（`PhysicalLayoutBinding`），Semantic 层不带任何几何信息（validators 强制）。
- 输出符合 `schemas/semantic-document` 的 `SemanticDocument`。

## Phase 2.4 — Dummy Translation（`packages/python/llm`）

- `paper_llm` 实现 `DummyTranslationProvider`：`translate(node) -> "[TRANSLATED] " + text`。
- 在每个 SemanticNode 的 translation 字段写入译文并保留原 identity，验证 SemanticNode id 稳定不变（translation 只改 content，不改 id）。最小接口 + 单测。

## Phase 2.5 — Minimal LaTeX Renderer

- 新建 `templates/latex/generic-academic.tex`：LuaLaTeX 模板，支持 heading（\section/\subsection）/ paragraph / figure / caption。
- 新建投影层 `src/pdf_pipeline/render_latex.py`（依据 `latex-render-model` note：SemanticDocument 与模板之间专用投影层，不在语义模型里拼 LaTeX；只此一个后端，不做 Renderer trait）。
- 文本转义（TeX 特殊字符）、figure 引用 physical 资源（渲染出的页面图片或提取图片）。
- `just latex-smoke` 保持可用；新增 e2e 编译目标 PDF 的测试。

## Phase 2.6 — Minimal RenderAnchor

- 投影时在每个节点的 LaTeX 输出中嵌入 marker（如 `\hypertarget{<nodeId>}{}` 或 invisible 标记）。
- 编译后用 PDFium 在 Target PDF 中搜索 marker 文本/链接注释，恢复 node → target page + bbox，写入 `MappingBundle`（`RenderAnchor` + `RenderBinding`）。
- 与 Phase 2.3 的 `SourceAnchor`（source PDF page/bbox）一起，建立 `SourceAnchor ↔ SemanticNode ↔ RenderAnchor` 三向映射，`validate_bundle_references` 全绿。

## Phase 2.7 — Minimal Viewer（`apps/web`）

- `apps/web` 引入 PDF.js（npm 依赖），双栏布局：左 Source PDF、右 Target PDF。
- 管线产物（mapping bundle JSON + 渲染页图或直接 PDF）由 dev server / `apps/api` 提供；点击 source 节点热区 → 高亮并滚动到 target 对应 region，反向亦然。
- Playwright e2e（`tests/e2e/`）：至少 Heading / Paragraph / FigureCaption 三种双向跳转各一条断言（对应 Roadmap Validation）。

## 端到端闭环与回归

- 新建管线编排入口（`src/pdf_pipeline/pipeline.py`，CLI：`python -m pdf_pipeline run <input.pdf> <outdir>`）：一次跑完 Physical → Layout → Semantic → Translation → LaTeX 编译 → RenderAnchor，输出 5 个 JSON + target PDF。
- 选用 Tier-1 合成夹具 `smoke` 与 `two-column` 的 PDF 作为端到端 golden 回归（按 `docs/testing/golden.md` 与 pdf-regression skill 流程建 golden；golden 只反映正确行为，不为过测试改 golden）。

## 风险与对策

- **pypdfium2 安装**（预编译 wheel，arm64 macOS 支持）：若安装受阻，退路是 PyMuPDF（AGPL，需许可评估）——仅在 pypdfium2 失败时再向用户确认。
- **RenderAnchor 恢复的精度**：marker 方案用 PDFium 全文搜索 + 链接注释双通道，容忍粗粒度（页级即可接受）。
- **真实论文许可**：只用 CC-BY / arXiv 公开论文，PDF 不入库，脚本断言 + 记录入库。
- **LaTeX 编译环境**：已有 `just latex-smoke` 工具链，复用 `tex/latexmkrc`。
