## 准入结论

**可以开始 M8 初版批次 A–E。**

三项 PRD 表面均达到「已实现 + 合成夹具通过」。MinerU / Docling / GROBID 的真实工具输出未验证，因此：

- 不阻塞本地 workspace、任务恢复、缓存与失败隔离；
- 阻塞把**内置** capability registry 的 primary 换成 `mineru` / `docling` / `grobid`（覆盖入口已存在，剩下的阻塞是证据而不是接线）；
- 不得在证据补齐前当作已通过。

`paragraphLabelRecall` / `headingLabelRecall` 是 `PARAGRAPH_LIKE` / `HEADING_LIKE` 区域召回，不是段落合并或章节树准确率。`paper-anatomy` / `table-heavy` / `tikz-vector` 上前者为 null，因为真值未标 `PARAGRAPH_LIKE`，不是语义能力失败。

远端 GitHub `CI / gate` 最后一次成功对应 `origin/main` 的 `059f1e7`（2026-09-16，批次 F 文档收口；typescript / python / rust / latex / docs / security 与 gate 全绿）。批次 F 已推送（`9405dcc`、`f2abfca`、`2607889`、`3da225f`、`c90fd95`、`059f1e7`）；其记录的 e2e 验收在本地跑绿（`just test-e2e`，14/14），远端 CI 不排程 Playwright。

## 分批计划

### A. 本地 workspace 与阶段状态

**依赖：** 无（M8 起点）。

**涉及文件（预计）：** `packages/python/pdf-pipeline/src/pdf_pipeline/pipeline.py`；新 workspace 清单模块（勿放入 `apps/`）；[`docs/architecture/storage.md`](../architecture/storage.md)（今日仍「有意未决」）；schema 仅当需要非 canonical 的 ad-hoc `workspace.json`（与 `probe.json` 同类，不进冻结 schema，除非另有 note）。

**要约定：** 阶段枚举 INGEST → PHYSICAL → EVIDENCE → LAYOUT → SEMANTIC → TRANSLATE → RENDER → INDEX；每阶段状态、产物路径、生产者版本、输入指纹；目录级原子提交（已有 viewer 发布回滚可复用）。

**验收：** 中断后重启只重跑未完成阶段，已完成 JSON/PDF 仍在；半写入目录不能被下一轮当成成功。

**just：** `just test-python`（新 workspace 单测）、`just docs-fast`。

### B. 最小任务编排、失败追踪、重试与重启恢复

**依赖：** A。

**涉及文件：** `apps/api`（任务状态，不只 `POST /api/retranslate`）、`apps/worker`（从 stub 变成调用 pipeline Job，业务逻辑仍在 `pdf-pipeline`）、pipeline 阶段入口。

**验收：** 失败写出 Issue 且任务可重试；进程被杀后读取 A 的阶段状态继续；不丢已完成产物。

**just：** `just test-python`、`just test-ts`（若 API 契约变）、相关 API 单测。

### C. 依赖图、缓存键、失效传播、局部重跑

**依赖：** A、B。

**涉及文件：** `paper_llm/cache.py`、`paper_llm/translation.py` 的 `_cache_key`、`rerender_workspace`、新阶段缓存键（physical/evidence/layout/semantic 的 content + 配置 + 代码/schema 版本）。

**验收：**

- 重译不重跑 physical/layout/semantic（已有测试可加强）。
- parser dump、registry、源 PDF 字节变化使依赖下游失效。
- 缓存不跨配置、版本、源文件误命中。

**just：** `just test-python`、`just test-golden`（若 viewer/workspace 契约变）。

### D. specialist 失败隔离与显式降级

**依赖：** A（Issue 落盘）、C（失败不得污染缓存）。

**涉及文件：** `pdf_pipeline/routing.py` 的 `collect_bundles`（今日一处异常即整链失败）、`fusion.py`、`sem_tables.py` 行 fallback、IssueStore。

**验收：** Docling 类失败 → TABLE 行 fallback + Issue，文档其余节点继续；不得把整篇标成 parse failed。

**just：** `just test-python`、`just benchmark`（fallback 不得引入新的 ERROR/FATAL，也不得为转绿改 baseline）。

**落地：** `collect_bundles` 返回 `ProviderCollection(bundles, degradations)`；provider 异常隔离为 capability 级降级（registry `fallback` 顶替，已收集实例复用、只降一级、不递归），无顶替则退回内建基线；每个失败产出归属该 provider 的 `ERROR` Issue（既有 `IssueCategory`，`fallback` 记顶替者或内建描述）与 `probe.json.degradations`；EVIDENCE 以 `degraded` 提交，下次运行重跑该阶段而下游继续；只有所有 routed provider 全失败才让阶段真失败。当前态与缓存语义见 [存储](../architecture/storage.md)，决策理由见 [批次 D note](../../.agents/notes/implemented/architecture/2026-09-15-m8-batch-d-specialist-isolation.md)。

### E. 旧 workspace 兼容、parser 配置与替换

**依赖：** A 的版本字段。真实 dump 若仍不可得，本批只做「拒绝静默读取未知版本」与配置入口，并把真实工具验证继续标为缺口。

**涉及文件：** `data/capability-registry.toml`、`routing.py`、workspace 版本迁移或明确错误、文档中的配置说明。不把模型/Java 写入默认依赖。

**验收：** 旧 workspace 可读、可迁移或明确拒绝，禁止静默破坏；切换 parser 必须改配置并失效 C 的下游缓存；默认 registry 仍是 sim，直到真实输出样本与 `just benchmark` 证明升级。

**just：** `just test-python`、`just schema`（若有 schema 变更）、`just benchmark`（仅在有意替换 primary 时）。

**落地：** 「可读 / 可迁移 / 拒绝」三态落地为**具名可读集合 + 明确拒绝**：`workspace.py` 新增 `SUPPORTED_WORKSPACE_VERSIONS = ("0.1.0",)`，集合外版本在 `_load_existing` 里任何 `self.*` 赋值之前抛出 `WorkspaceVersionError`，消息含清单路径、写入版本、本构建可读版本与重建指引，「不触碰磁盘」由测试以清单字节不变 + 无 `.staging` 钉住。本批**不写版本转换函数**：批次 A–D 写的都是 `"0.1.0"`，清单形状从未变过（C 改键材料、D 加 status 取值），旧 workspace 因缓存键自然失配重跑而非被拒，写转换器只会是死代码；未来 bump 时要么把旧版本加进集合并补真实迁移步骤，要么保持拒绝。parser 配置入口新增 `pdf_pipeline/config.py`（`ParserConfig` + `load_parser_config`，镜像 `paper_llm.config`，唯一 env 读取者）：优先级 `--registry` flag > `PAPER_CAPABILITY_REGISTRY` > 内置 registry。`capabilities` 全面参数化：`load_registry(path=None)`、新 `registry_text(path=None)`、`registry_fingerprint(path=None)` 与单次读取的 `resolve_registry(path=None) -> (Registry, digest)`；覆盖文件每次实读、不缓存，内容（而非路径）入键，解析/校验失败一律抛新 `CapabilityRegistryError`（`ValueError` 子类）且**绝不回退内置**。`run_pipeline(..., pipeline_config=...)` 在构造 workspace **之前**解析 registry，把 digest 经 `stage_config_inputs(..., registry_digest=...)` 折进 EVIDENCE/LAYOUT 键，并把同一个 `Registry` 传给 `_run_evidence_stage` / `_run_layout_stage`（不再各自 `load_registry()`）；`rerender_workspace` 不需要该参数——它只重写 TRANSLATE/RENDER 记录，那两个阶段的配置项不含 `capabilityRegistry`。`tests/benchmark/run_benchmark.py` 改走同一 env 入口，故「用覆盖 registry 跑 benchmark 证明升级」是一条命令。`data/capability-registry.toml` 未改，primary 仍是 `mock` / `docling-sim` / `grobid-sim`。真实工具输出仍是缺口。决策理由见 [批次 E note](../../.agents/notes/implemented/architecture/2026-09-15-m8-batch-e-parser-config-and-workspace-version.md)。

### F. 本地产品端到端验收

**依赖：** A–E 的已交付部分；parser 真实工具仍可缺，但产品流须在 sim ensemble 上走通。

**涉及文件：** `apps/web`、`apps/api`、`tests/e2e`、`just serve-reader`。

**验收：** PRD §40：导入 → 分析 → 翻译 → 生成 Target PDF → Source/Target 互跳。发布失败后 Viewer 仍读上一 revision。

**just：** `just test-e2e`、`just latex-smoke`、`just benchmark`、`just ci`。

**落地：** PRD §40 现在在运行中的栈上走通：`just serve-reader`（与 Playwright webServer）起 API + worker + Vite 三进程；`apps/web` 的最小路径式导入面板（现在渲染在 upload 标签面板的 `#import-panel` 内）提交不带 `viewerDataDir` 的 `POST /api/jobs`（API 把它默认成服务端自己的 `--data-dir`，作业因此发布到 viewer 正在读的目录），面板轮询作业并经新增的 `DualPaneReader.load()` 就地换到 Job 发布的修订；`tests/e2e/product-import.spec.ts` 用真实的第二份文档（tikz-vector）证明导入 → 分析 → 翻译 → Target PDF → 双向互跳。「发布失败后 Viewer 仍读上一 revision」由 `tests/e2e/publish-failure.spec.ts` 经 `_commit_prepared_file` 上文档化的 `PAPER_PUBLISH_FAULT` 缝在 HTTP 层证明：retranslate 返回 500，manifest、全部稳定别名与 `revisions/` 集合逐字节不变，viewer 在上一修订上 boot 并完成跳转。理由见 [批次 F note](../../.agents/notes/implemented/architecture/2026-09-16-m8-batch-f-local-e2e.md)。
