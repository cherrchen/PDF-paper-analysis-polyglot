## Admission conclusion

**M8 v1 batches A–E may start.**

All three PRD surfaces are “implemented + synthetic fixture passed”. Real-tool MinerU / Docling / GROBID output is not verified, so:

- it does not block local workspace, task recovery, cache, or failure isolation;
- it does block swapping a *bundled* capability-registry primary to `mineru` / `docling` / `grobid` (the override entry point now exists, so the remaining blocker is the evidence, not the plumbing);
- it must not be reported as passed until the evidence exists.

`paragraphLabelRecall` / `headingLabelRecall` are `PARAGRAPH_LIKE` / `HEADING_LIKE` region recall, not paragraph-merge or section-tree accuracy. They are null on `paper-anatomy` / `table-heavy` / `tikz-vector` because those truth files do not label `PARAGRAPH_LIKE`, not because semantic recovery failed.

The last successful remote GitHub `CI / gate` is `origin/main` at `1f78750` (2026-09-15, the Vale repair after batch E landed; typescript / python / rust / latex / docs / security and the gate all passed). Batch E has been pushed (`6863c11`, `7300aa4`, `d797ffa`, `1f78750`).

## Batch plan

### A. Local workspace and stage state

**Depends on:** nothing (M8 start).

**Likely files:** `packages/python/pdf-pipeline/src/pdf_pipeline/pipeline.py`; a new workspace inventory module (not under `apps/`); [`docs/architecture/storage.md`](../architecture/storage.en.md) (today still “intentionally unresolved”); schema only if an ad-hoc `workspace.json` is needed (same class as `probe.json`, outside frozen schemas unless a new note says otherwise).

**Must define:** stage enum INGEST → PHYSICAL → EVIDENCE → LAYOUT → SEMANTIC → TRANSLATE → RENDER → INDEX; per-stage status, artifact paths, producer versions, input fingerprints; directory-level atomic commit (reuse viewer publish rollback).

**Acceptance:** after interrupt-and-restart, only unfinished stages rerun and completed JSON/PDF remain; a half-written directory must not look successful to the next run.

**just:** `just test-python` (new workspace unit tests), `just docs-fast`.

### B. Minimal task orchestration, failure tracking, retry, restart resume

**Depends on:** A.

**Files:** `apps/api` (task status, not only `POST /api/retranslate`), `apps/worker` (call pipeline jobs; business logic stays in `pdf-pipeline`), pipeline stage entry points.

**Acceptance:** failures write Issues and the task can be retried; after a kill, the process reads A’s stage state and continues; completed artifacts are kept.

**just:** `just test-python`, `just test-ts` if the API contract changes, plus related API tests.

### C. Dependency graph, cache keys, invalidation, partial rerun

**Depends on:** A, B.

**Files:** `paper_llm/cache.py`, `_cache_key` in `paper_llm/translation.py`, `rerender_workspace`, new stage cache keys (physical/evidence/layout/semantic content + config + code/schema version).

**Acceptance:**

- Retranslation does not rerun physical/layout/semantic (strengthen existing tests).
- A parser dump, registry, or source-PDF byte change invalidates dependents.
- The cache does not hit across config, version, or source file.

**just:** `just test-python`, `just test-golden` if viewer/workspace contracts change.

### D. Specialist failure isolation and explicit degradation

**Depends on:** A (Issues on disk), C (failures must not poison the cache).

**Files:** `collect_bundles` in `pdf_pipeline/routing.py` (today one exception fails the chain), `fusion.py`, `sem_tables.py` line fallback, IssueStore.

**Acceptance:** a Docling-class failure → TABLE line fallback + Issue, other nodes continue; the whole document is not “parse failed”.

**just:** `just test-python`, `just benchmark` (fallback must not introduce new ERROR/FATAL, and must not rewrite the baseline to go green).

**Landed:** `collect_bundles` returns a `ProviderCollection(bundles, degradations)`; a provider exception is isolated as capability-level degradation (the registry `fallback` substitutes, reusing an already-collected instance, one level deep, no recursion; the internal baseline covers the rest); each failure produces one `ERROR` Issue attributed to that provider (existing `IssueCategory` values, `fallback` naming the substitutes or the internal description) plus a `probe.json.degradations` entry; EVIDENCE commits as `degraded`, so the next run reruns that stage while its downstream continues; only every routed provider failing makes the stage fail. Current state and cache semantics: [storage](../architecture/storage.en.md); rationale: the [batch D note](../../.agents/notes/implemented/architecture/2026-09-15-m8-batch-d-specialist-isolation.en.md).

### E. Old workspace compatibility, parser configuration and replacement

**Depends on:** A’s version field. If real dumps are still unavailable, this batch only refuses unknown versions silently and adds the config entry, keeping real-tool verification as a gap.

**Files:** `data/capability-registry.toml`, `routing.py`, workspace version migrate-or-explicit-error, configuration docs. Do not put models/Java in default dependencies.

**Acceptance:** an old workspace is readable, migrated, or explicitly refused — never silently corrupted; switching parser changes config and invalidates C’s downstream caches; the default registry stays sim until real output samples plus `just benchmark` justify an upgrade.

**just:** `just test-python`, `just schema` if schemas change, `just benchmark` only when intentionally replacing a primary.

**Landed:** "readable / migrated / refused" became a **named readable set plus explicit refusal**: `workspace.py` gains `SUPPORTED_WORKSPACE_VERSIONS = ("0.1.0",)`, and a version outside it raises `WorkspaceVersionError` in `_load_existing` before any `self.*` assignment, with a message carrying the manifest path, the written version, the versions this build reads, and the rebuild guidance; "no disk touch" is pinned by a test asserting unchanged manifest bytes and no `.staging`. This batch writes **no version converter**: batches A–D all wrote `"0.1.0"` and the manifest shape never changed (C changed the key material, D added a status value), so an old workspace reruns through stale cache keys instead of being refused, and a converter would be dead code; a future bump either adds the old version to the set with a real migration step, or keeps refusing. The parser configuration entry point is the new `pdf_pipeline/config.py` (`ParserConfig` + `load_parser_config`, mirroring `paper_llm.config` as the single environment reader): precedence `--registry` flag > `PAPER_CAPABILITY_REGISTRY` > bundled registry. `capabilities` is parameterized throughout: `load_registry(path=None)`, a new `registry_text(path=None)`, `registry_fingerprint(path=None)`, and the single-read `resolve_registry(path=None) -> (Registry, digest)`; an override file is read fresh (never cached), content — not path — enters the key, and any parse/validation failure raises the new `CapabilityRegistryError` (a `ValueError` subclass) with **no fallback to the bundled registry**. `run_pipeline(..., pipeline_config=...)` resolves the registry **before constructing the workspace**, folds the digest into the EVIDENCE/LAYOUT keys through `stage_config_inputs(..., registry_digest=...)`, and hands the same `Registry` to `_run_evidence_stage` / `_run_layout_stage` (which no longer call `load_registry()` themselves); `rerender_workspace` needs no such argument — it rewrites only the TRANSLATE/RENDER records, whose config items contain no `capabilityRegistry`. `tests/benchmark/run_benchmark.py` goes through the same environment entry point, so "prove an upgrade with an overriding registry" is one command. `data/capability-registry.toml` is unchanged; the primaries stay `mock` / `docling-sim` / `grobid-sim`. Real tool output remains a gap. Rationale: the [batch E note](../../.agents/notes/implemented/architecture/2026-09-15-m8-batch-e-parser-config-and-workspace-version.en.md).

### F. Local product end-to-end acceptance

**Depends on:** delivered parts of A–E; live parsers may still be missing, but the product flow must pass on the sim ensemble.

**Files:** `apps/web`, `apps/api`, `tests/e2e`, `just serve-reader`.

**Acceptance:** PRD §40: import → analyze → translate → Target PDF → Source/Target jumps. After a publish failure the viewer still reads the previous revision.

**just:** `just test-e2e`, `just latex-smoke`, `just benchmark`, `just ci`.
