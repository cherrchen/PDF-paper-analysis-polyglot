# Agent Note: M7 Parser Ensemble & Quality System Landing

Status: implemented

[中文](./2026-09-12-m7-parser-ensemble.md) | [English](./2026-09-12-m7-parser-ensemble.en.md)

## Problem

At the end of M6 the pipeline hard-coded a single provider (`run_pipeline` called `MockLayoutEvidenceProvider` directly), conflict resolution was a plain confidence vote, and there was no probe, no capability registry, no routing. Quality was also unmeasurable: benchmarks only asserted, produced no report, so no provider/algorithm upgrade could be quantified as better or worse (the M7 Exit Gate demands upgrades become quantifiable engineering decisions). The M4/M5 items marked "target M7" (1 Layout→N Semantic, real multi-column table structure, GROBID bibliography specialist, author-year citations, STRUCTURE/METADATA specialists) were likewise pending.

## Decision

1. **DocumentProbe (Phase 7.1, `pdf_pipeline/probe.py`)**: derives `native_text_ratio / scanned_page_ratio / math_density / table_density / image_density / estimated_columns / layout_complexity` (the §41 field set) from the PhysicalDocument alone. The column estimate reuses per-page modal column counts from `page_structure.detect_bands`; the table signal reuses the providers/table_grid heuristics. Everything is a deterministic function of page objects. `run_pipeline` probes right after physical extraction and writes the ad-hoc artifact `probe.json` (probe values plus the RoutingPlan), **outside the canonical schemas** — same category as the viewer manifest; the schema compatibility freeze boundary is untouched.
2. **Capability Registry (Phase 7.2, `pdf_pipeline/capabilities.py` + `data/capability-registry.toml`)**: capability → provider order (primary/challenger/fallback) mirroring architecture doc §35, with provider names `pdfium / mock / docling-sim / grobid-sim / internal`. Implemented as **TOML + stdlib `tomllib`** instead of the doc's YAML sketch: zero new dependencies, deterministic parsing; migrate to runtime-editable config only if a deployment needs it (new note then). Loading enforces the invariants: `semantic.document`, `layout.reading_order`, `layout.column_detection` must stay internal-owned.
3. **Simulated specialist providers (`pdf_pipeline/evidence/fake_specialists.py`)**: real MinerU/Docling/GROBID are heavy (models/Java); per roadmap Step 4 everything runs on deterministic baselines — `docling-sim` emits `TABLE_STRUCTURE` candidates (row/column/cell grids), `grobid-sim` emits scholarly `METADATA` (title/author/abstract) and `STRUCTURE` (section/REFERENCES/ABSTRACT roles) candidates. Real adapters plug into the same `EvidenceProvider` Protocol later with no mechanism change. The shared `_CandidateSink` is now public (`CandidateSink`) with per-provider ID-prefix namespacing so parallel bundles never collide.
4. **Adaptive Routing (Phase 7.3, `pdf_pipeline/routing.py`)**: `route_providers(probe, registry) -> RoutingPlan` is a pure function — the layout primary always runs; `table_density ≥ 0.1` wakes docling-sim; `math_density ≥ 0.05` tags the layout primary with the formula capability; scholarly metadata/bibliography runs on every paper (the §42 standard route); textless documents are refused (consistent with the FR-PDF-002 entry gate). `run_pipeline` feeds the routed bundle list to `recover_layout_document` (per-bundle provider attribution preserved) and a merged ensemble bundle to semantic recovery and `evidence.json` (provider field records `ensemble:<names>`; per-provider attribution remains traceable through provenance `producer` strings).
5. **Conflict Resolution (Phase 7.4, `fusion.py`)**: label voting changed from pure confidence to **confidence × authority weight** (primary 1.5 / challenger 1.2 / fallback 1.0 / unlisted 0.8), with the capability mapped from the label (TABLE→table.structure, FORMULA→formula.detection, else layout.region). Weights use **role slots**, so an empty challenger/fallback must not promote a fallback or unlisted provider to challenger. `fuse_page` clusters candidates for the same region, then runs one vote (including TABLE/FORMULA). Simple majority voting stays forbidden (§43). With no registry (None) behavior degrades to the old vote. Review repairs: [M7 review repairs](../bug-fix/2026-09-12-m7-review-repairs.en.md).
6. **1 Layout→N Semantic (Phase 4.1 deferred item, `sem_paragraphs.py`)**: `split_region_paragraphs` splits one region's lines into paragraph pieces on "line gap > 1.5× line height" and embedded numbered headings; **both the split decision and heading classification** reuse `heading_decision(numbered_only=True)` (math-guarded, `2 dx = dy` does not split). If one region in a continuation group splits 1→N, non-heading pieces on the boundary still join with `join_region_text` and keep every source region on the SourceAnchor. Embedded headings do not open a new SECTION (re-parenting deferred).
7. **Structured table chain (Phase 4.4 deferred item)**: physical `_extract_text_spans` now re-splits a PDFium rect at char gaps beyond 3× line height — table column gaps are 39–63pt while word/sentence spaces stay ≤16.9pt, so only table cells split and prose spans keep PDFium's exact granularity (the zero-regression precondition for benchmarks/golden). Shared `table_grid.py` detects grids: runs of consecutive aligned multi-span lines + column gap ≥ 0.25× narrower column width (rejects cross-column gutters) + run length ≤ 12 (rejects multi-column body). docling-sim emits TABLE_STRUCTURE and the existing `sem_tables` structured path consumes it.
8. **Author-year citations (Phase 4.7 deferred item, `sem_bibliography.py`)**: `(Surname et al., YYYY)` / `(A & B, YYYY)` / year suffixes (2020a) parse into `surname:year` keys matched against bibliography entries (first capitalized token after the `[n]` label + year), producing CITATION marks + CITES relations; unresolved markers still surface as CITATION_RESOLUTION issues. New Tier-1 fixture `author-year-citations` (includes the 2020a disambiguation suffix).
9. **Scholarly metadata → front matter (Phase 4.2 gap)**: `classify_front_matter` gained a `metadata` parameter; grobid-sim title/author values confirm or fill the title/author roles of the page-1 prefix block (a fallback for when the heuristic has no HEADING_LIKE line).
10. **Confidence Calibration (Phase 7.5, `pdf_pipeline/calibration.py`)**: binning harness ([0, 0.5, 0.6, 0.7, 0.8, 0.9, 1.0] edges with per-bin counts/accuracy and a monotonicity diagnostic). **Numeric calibration is a diagnostic, not a gate**: `compare()` writes accuracy movement as `diagnostic` lines and never marks them `REGRESSED`. The hand truth is snippet-level (readingOrder lists key regions only), so unmatched regions cannot be graded as negatives — region-level labeled truth is the prerequisite (same stance as M3's "Region Precision pending region-level annotation").
11. **Quality Metrics (Phase 7.6, `metrics.py::quality_report`)**: aggregates physical text coverage, region recall/precision, pairwise/sequence ordering, `semanticExpectationCoverage` (kinds / minCounts expectation satisfaction), table-structure coverage, citation resolution rate, source/render mapping coverage, and issue counts by category and severity. Layout-label recall stays null without region-level truth; ERROR presence or kind checks are not reported as accuracy. Later renamed to `paragraphLabelRecall` / `headingLabelRecall` (layout-label recall, not paragraph merge or the section tree); see [M8-pre review repairs](../bug-fix/2026-09-12-m8-pre-review-repairs.en.md).
12. **Regression Benchmark (Phase 7.7, `tests/benchmark/run_benchmark.py`)**: runs the routed ensemble over every built fixture → produces the report → compares against `tests/benchmark/baseline.json` (higher-is-better, epsilon 1e-3). Non-zero exit on: a measurable metric drop, a baseline fixture missing from the current report, a previously measurable metric becoming null, or an ERROR/FATAL count increase. WARNING/INFO are recorded, not gated. `just benchmark` / `benchmark-report` / `benchmark-update-baseline`; the nightly workflow runs the gate after `just latex-smoke`. Baseline updates follow the golden policy (the commit message must justify them).

## Alternatives considered

- **Full char-level re-clustering in the physical layer** (first implementation): replaced PDFium rects entirely with loose charboxes. It inflated the span height distribution → body_font drift → cascading heuristics shifts (equation numbers lost, column structure drifted); reverted. The narrow approach (re-split only at intra-rect gaps > 3× line height) reaches the same table goal with zero benchmark/golden regressions.
- **YAML registry + pyyaml dependency**: TOML (stdlib tomllib) is dependency-free and equally expressive; the §35 YAML sketch was only a form.
- **table_region_candidates (numeric-row heuristic) producing structure**: it assumes whole-row single spans, which cell splitting breaks; replaced by shared grid detection (mock emits REGION candidates, docling-sim emits structure).
- **Wiring real MinerU/Docling/GROBID this round**: heavy dependencies (models/Java); simulated providers already validate the ensemble mechanics and real adapters plug in via the same Protocol (promised in providers.py docstring).
- **Gating on calibration numbers**: truth granularity is insufficient (see decision 10); absolute accuracy is meaningless. Calibration movement is diagnostic only; the gate watches fixtures, measurable metrics, and ERROR/FATAL counts.

## Consequences

- `run_pipeline` gains `probe.json` (ad-hoc, non-canonical); `evidence.json`'s `provider` field becomes `ensemble:<names>`; `rerender_workspace` does not read evidence, so re-rendering is unaffected.
- Layout output for the same PDF **changes** versus M6 (table-row span splitting + authority weights + ensemble candidates); layout/semantic benchmarks and golden passed with zero regressions before landing, and the committed baseline freezes the M7 state.
- Header rows (unsplit whole-row rects) are not part of TABLE_STRUCTURE cells yet (their column gaps are below the threshold); their text remains a separate TEXT region — content is not lost (quality priority 1); merging headers into cells awaits the real specialist source.
- `table_grid_regions` guards multi-column body pages with the row-run cap and the proportional column-gap check; new false-positive shapes should tune `TABLE_MAX_GRID_ROWS`/`COLUMN_GAP_RATIO` via the benchmark report.
- Verification: see [M7 review repairs](../bug-fix/2026-09-12-m7-review-repairs.en.md); e2e unaffected (viewer data contract untouched).
- Docs: `docs/development/roadmap.en.md` M7 detail rows and this note were the baseline at landing.
