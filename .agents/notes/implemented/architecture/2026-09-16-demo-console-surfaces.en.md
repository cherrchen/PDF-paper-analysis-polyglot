# Agent Note: Demo Console Surfaces and Floating Panel Column

Status: implemented

[中文](./2026-09-16-demo-console-surfaces.md) | [English](./2026-09-16-demo-console-surfaces.en.md)

## Problem

After [batch F](./2026-09-16-m8-batch-f-local-e2e.en.md) the only write path in the browser was a path-style import panel squeezed into `#reader-toolbar`: trying a paper meant typing two absolute paths, and nothing showed previously run workspaces, job history, or whether a worker was alive. The Semantic Inspector was a sibling node at `flex: 0 0 320px` that ate PDF display width outright, and the page itself was not fit-width. The hand-drawn sketch requires "overlay shows the specific region, consuming no PDF display width" — every right-hand panel should float above the PDFs.

Three new needs had no server-side support at all: enumerating existing workspaces (only the job queue existed, no workspace listing), handing browser bytes to the server (`POST /api/jobs` accepts absolute paths only), and deciding whether a worker is alive (previously inferable only from queue length and flock state). Four scope decisions were confirmed this round: select is read-only enumeration plus synchronous republish (no new stage, no LLM/LaTeX, no worker needed); upload is a real upload whose workspace path the server derives; the panel shape is a right-hand floating drawer that consumes no PDF width; status adds a worker heartbeat file and `GET /api/status`.

## Decision

1. **The four-surface split comes from the hand-drawn sketch.** The four `role="tab"` buttons in `#surface-tabs` (`#tab-upload` / `#tab-select` / `#tab-history` / `#tab-status`) each control one `role="tabpanel"` inside `#surface-panels`; `apps/web/src/surface-tabs.ts::bootSurfaceTabs()` is the single source of state (clicking the open surface closes it, at most one panel is visible) and `onChange` lets select/history refresh their lists and status start and stop its 3 s poll. `#inspector` moved into that same column, with DOM order fixed to upload → select → history → status → inspector so a tab panel renders above the region info card when both are visible.
2. **Floating drawer, no PDF width taken.** `#surface-panels` is absolutely positioned at the top right of `#reader-body` (`top: 0; right: 0; bottom: 3.5rem; width: min(360px, 34vw)`, container `pointer-events: none`, cards `pointer-events: auto`), and `#inspector`'s old `flex: 0 0 320px` rule is gone. `bottom: 3.5rem` parks the drawer above each pane's bottom-right `.page-controls`, so the `1 / N` page number and Previous/Next stay clickable. Its price is covering regions at the right edge of the right pane: e2e specs that must click a region `uncheck("#inspector-toggle")` first, and product behavior is unchanged (`#inspector-toggle` stays checked by default because `viewer-inspector.spec.ts`'s hide/restore case depends on its initial visibility).
3. **Fit-width and ratio scrolling.** Each `.page-scroll` scrolls vertically only and `.page-stage canvas` is `width: 100%; height: auto`, so both PDFs always scale to the column width with no horizontal scrollbar. The canvas pixel height is therefore no longer known: `canvasHeight` is removed from `reader-overlay.ts::PageMetrics`, `pane-render.ts::RenderCommit`, and `reader.ts::commitPage`, and `scrollFragmentIntoCenter` / `syncFrom` convert through `container.scrollHeight` ratios instead.
4. **Upload is a real upload and the server derives every write path.** `POST /api/uploads` takes the raw PDF bytes (`X-Upload-Name`; it streams into `<jobs-root>/inbox/.{slug}.part` while accumulating a sha256, capped at 64 MiB, first 5 bytes must be `%PDF-`), lands them as `<jobs-root>/inbox/{slug}-{sha256 first 8}.pdf`, and derives the workspace path as `<jobs-root>/workspaces/{slug}-{sha256 first 8}` (a directory `run_pipeline` creates). The file name and the content digest together name the stored file, so re-uploading the same file name with identical bytes reuses one inbox file and one workspace.
5. **select republishes already-committed artifacts; it reruns no stage.** New `pipeline.republish_workspace_viewer(workspace_dir, *, viewer_data_dir)` only republishes committed artifacts as a fresh viewer revision. The reason is that "open" must have no side effects: routing it through a job rerun would consult the `run_pipeline` stage cache keys, and any configuration drift would trigger real provider calls plus a whole-document LaTeX recompile (minutes, money, possibly different translations). The front end's `Open` is therefore `POST /api/workspaces/open` plus `DualPaneReader.load()`, never a job submission.
6. **`republish_workspace_viewer` writes nothing into the workspace.** It calls no `commit_stage` and writes no `viewer-publication.json`; it only writes a new revision in the viewer directory and atomically flips the manifest, so the INDEX publication receipt stays owned by `run_pipeline` / `rerender_workspace`. Target-side anchors are recovered on the spot by `recover_render_anchors(target.pdf, semantic)` because canonical mapping carries only source-side bindings. Preconditions are that every stage except INDEX still has `artifacts_intact` and that `mapping.json` exists, otherwise it raises `WorkspaceError`.
7. **A worker heartbeat replaces inferring liveness from the queue.** `<jobs-root>/worker.json` carries six keys (`heartbeatVersion` / `pid` / `startedAt` / `updatedAt` / `concurrency` / `running`); `run_forever` rewrites it atomically every 2 s (`HEARTBEAT_INTERVAL_S`) from a daemon thread, and `run_once` plus normal exit delete it; `GET /api/status` treats `ageSeconds <= HEARTBEAT_STALE_S` (15 s) as `alive`. A failed heartbeat write is swallowed — a heartbeat must never kill the worker.
8. **Read/write boundary of the two new writing endpoints.** `POST /api/workspaces/open` accepts only a **read** source (an absolute workspace path that must already carry `workspace.json`) and always writes into the server's own `--data-dir`; `POST /api/uploads` likewise takes only bytes, with the server naming both the inbox file and the workspace. This is the same rule as `/api/retranslate` resolving its document from the current manifest binding instead of accepting a client write path.

## Alternatives considered

- **Make the drawer an occupying right column.** The hand-drawn sketch explicitly requires taking no PDF width; an occupying column shrinks each pane's page width and directly conflicts with the fit-width goal. The overlap cost is handled by unchecking `#inspector-toggle` in e2e instead of reverting the drawer to a width-consuming layout.
- **Have select rerun the same workspace through `POST /api/jobs`.** See decision 5; on top of that, a job record would present "just opening" as a real run, distorting the history surface.
- **Have select reuse `rerender_workspace` (the zero-source-re-parse retranslation chain).** It still needs provider calls and a whole-document LaTeX recompile (seconds to tens of seconds), an unnecessary side effect for "open".
- **Default `#inspector-toggle` to unchecked.** Less overlap, but `viewer-inspector.spec.ts`'s hide/restore case depends on initial visibility, and region info is this product's primary evidence panel — defaulting it off hides the evidence.
- **Infer worker liveness in `GET /api/status` from queue length and flock.** An empty queue cannot distinguish "worker idle" from "no worker running", and flock only says some process once held the lock. An explicit heartbeat is the only signal that tells the two apart.
- **Land uploads in a client-specified directory.** That hands the server's write target to the caller; both the `inbox/` name and the workspace name are derived server-side from the file name and the content digest, and the client supplies only a display name and bytes.

## Consequences

- `apps/api`: new `paper_api/workspaces.py`, `uploads.py`, and `status.py`; `__main__.py` gains the `/api/workspaces`, `/api/workspaces/open`, `/api/uploads`, and `/api/status` routes, their 405 sets, and a connection read timeout dedicated to uploads, while `make_handler(workspace, data_dir, jobs_root)` keeps its signature.
- `pdf-pipeline`: new `workspace.{WorkspaceSummary, summarize_workspace, discover_workspaces}` and `WorkspaceManager.{load, artifacts_intact}` (all write nothing), `pipeline.republish_workspace_viewer`, and the `jobs` heartbeat constants plus functions (`HEARTBEAT_STALE_S = 15.0`). `apps/worker` needs no code change and `paper_worker.status()` stays as it is.
- `apps/web`: `index.html` is replaced wholesale (every existing id preserved; `#inspector-toggle` becomes a checkbox instead of a button), new `surface-tabs.ts` / `select-panel.ts` / `history-panel.ts` / `status-panel.ts` / `jobs-client.ts`, `reader.ts` drops `canvasHeight` and switches to ratio scrolling, and `main.ts` boots the tabs plus the four panels. The console's visual language and masthead primary action are now specified by the [2026-09-17 Overleaf-style design-system note](./2026-09-17-overleaf-console-design-system.en.md), while decisions 1–8 of this note (the four-surface split, the floating drawer, fit-width, and the upload/select/status behavior) remain current.
- e2e: new `console-surfaces.spec.ts` (opening and closing the four surfaces, `API ok`, non-empty history, and `#viewer`'s `data-revision` changing after `Open` in select); existing specs that must click a region `uncheck("#inspector-toggle")` first.
- Docs: console surfaces in [`reader.en.md`](../../../../docs/architecture/reader.en.md) (replacing the batch F import-panel section), endpoints in [`api.en.md`](../../../../docs/architecture/api.en.md), inbox / heartbeat / as-is republication in [`storage.en.md`](../../../../docs/architecture/storage.en.md), and the §F landed wording in [`m8.en.md`](../../../../docs/development/m8.en.md).
- Left open: `republish_workspace_viewer` publishes a new revision on every call (even when that workspace is already current), costing about 1.5 MB of writes; what it buys is that clicking Open is always observable. To save that write later the criterion is `_viewer_current(workspace_dir, viewer_data_dir)`, but that also means accepting "the revision does not change after clicking Open". If a historical workspace has incomplete artifacts, `Open` returns 400 with the missing stage names in the error string, and recovery is the history surface's `Retry` or re-running the upload — no automatic repair is implemented.
