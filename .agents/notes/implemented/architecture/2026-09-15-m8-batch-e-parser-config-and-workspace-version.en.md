# Agent Note: M8 batch E parser configuration entry point and old-workspace version policy

Status: implemented

[中文](./2026-09-15-m8-batch-e-parser-config-and-workspace-version.md) | [English](./2026-09-15-m8-batch-e-parser-config-and-workspace-version.en.md)

## Problem

[`docs/development/m8.md`](../../../../docs/development/m8.en.md) §E requires that "an old workspace is readable, migrated, or explicitly refused — never silently corrupted" and that "switching parser changes config and invalidates C's downstream caches", but batches A–D deferred both boundaries explicitly: `workspace.py` only said "migration belongs to M8 batch E", and [`storage.md`](../../../../docs/architecture/storage.en.md) said "migration belongs to batch E" in two places. Two things were missing at landing time.

First, version handling was a single inequality: `version != WORKSPACE_VERSION` raises `WorkspaceVersionError` with a message that only says "expected '0.1.0'" — no "which file is this, what can this build read, what should I do", and no named readable set. Bumping `WORKSPACE_VERSION` would force nobody to face the question "is the old version still readable?".

Second, and the harder gap: **there was no registry override entry point at all**. `capabilities._registry_text()` read package data directly, and `run_pipeline`, the CLI, and `apps/` had no registry argument or environment variable, so switching parser meant editing `data/capability-registry.toml` in the source and restarting. On top of that, `registry_fingerprint()` always hashed the bundled bytes, so even with an entry point, if the fingerprint did not follow the registry **actually used**, §E's "switching parser invalidates the downstream cache" could never hold — the override takes effect while the cache key stays put, which is silent staleness.

Real MinerU / Docling / GROBID output is still unavailable this round, so this batch only adds the configuration entry point and a named refusal policy, keeping real-tool verification as a gap (`provenance.json` is entirely `synthetic-contract`, and the bundled primaries stay `mock` / `docling-sim` / `grobid-sim`).

## Decision

1. **"Readable / migrated / refused" becomes a named readable set plus explicit refusal.** `workspace.py` gains `SUPPORTED_WORKSPACE_VERSIONS: tuple[str, ...] = ("0.1.0",)` — written as an explicit literal rather than derived from `WORKSPACE_VERSION`, because a derived form would silently drop the old version on a bump. `_load_existing` raises `WorkspaceVersionError` when `version` is not a string or not in the set, with a message carrying the manifest path, the written version, the versions this build reads, and the "use a new output directory, or delete the workspace to rebuild it" guidance. The `raise` still precedes any `self.*` assignment, so a rejected workspace is untouched on disk and in memory.
2. **This batch writes no version converter.** Batches A–D all wrote `"0.1.0"` and the manifest shape never changed: batch C changed the key material (config folded into `inputFingerprint`) and batch D added a status value (`StageStatus.DEGRADED`), neither of which changes a manifest field. An old workspace is therefore **still readable as it stands** and reruns naturally through mismatched keys — there is no old format to convert, so a converter would be dead code. A future bump picks one of two paths: add the old version to the set plus a real migration step in `_load_existing`, or keep refusing.
3. **Parser configuration has exactly one entry point**: the new `pdf_pipeline/config.py`, with `ParserConfig` (a frozen data class holding `registry_path: Path | None`) and `load_parser_config()`, deliberately mirroring the `TranslationConfig` + `load_translation_config` shape in `paper_llm.config` rather than introducing a second convention for reading the environment into a typed object. The environment variable is `PAPER_CAPABILITY_REGISTRY` (`REGISTRY_PATH_ENV`), named after the existing `Capability Registry` / `capability-registry.toml` vocabulary.
4. **Precedence is fixed at flag > env > bundled.** The CLI gains `--registry <file>`; `main` passes `ParserConfig(registry_path=args.registry) if args.registry else None`, so an absent flag passes `None` and lets `run_pipeline` read the environment; with no environment variable either, `registry_path` is `None` and the bundled registry applies.
5. **`capabilities` is parameterized throughout, and an override is never cached.** `load_registry(path=None)`: `None` → `_bundled_registry()` (an `lru_cache(maxsize=1)` wrapper over `_parse_registry(_registry_text(), source="bundled capability-registry.toml")`, which is safe to cache because package data is immutable within a process); a given path → read and parsed fresh every call. The new public `registry_text(path=None)` returns the raw TOML. `_load_registry_impl` is renamed `_parse_registry(text, *, source)`, and `_validate(registry, *, source)` takes the source too.
6. **The override file's content enters the key; its path does not.** `registry_fingerprint(path=None)` becomes `sha256(registry_text(path))`: with an override the digest follows the override's content, which is exactly how §E's acceptance clause is implemented. The same content at two different paths yields one digest, and a byte-identical copy of the bundled registry triggers no rerun at all.
7. **A single-read `resolve_registry(path=None) -> tuple[Registry, str]`.** A run must route with exactly the registry its stage keys describe: reading twice would let an edit between the two reads record a digest that does not match the artifacts — a silent cache hit. With `path is None` it returns the cached bundled table and digest; otherwise one `registry_text` read yields the text from which both the table and the digest are derived.
8. **A broken configuration is always refused, never silently resolved to the bundled registry.** The new `CapabilityRegistryError(ValueError)` (inheriting `ValueError`, so existing `pytest.raises(ValueError)` expectations still hold) covers read failures (`OSError` / `UnicodeError`), TOML parse failures, and every `_validate` invariant violation (a missing internal capability, an internal capability owned by something other than `internal`, a provider listed twice for one capability); messages always name the source (a path, or `bundled …`). A silent fallback to the bundled registry is a silent parser swap — the single least acceptable behavior in this batch.
9. **`run_pipeline` resolves the registry once, before constructing the workspace, and passes it down.** It gains the keyword argument `pipeline_config: ParserConfig | None = None`; `registry, registry_digest = resolve_registry(parser_config.registry_path)` runs **before** `WorkspaceManager(...)`, because a broken registry must fail before any disk state is touched. `stage_config_inputs(config, source_bytes, *, registry_digest=None)` uses `registry_digest or registry_fingerprint()`; `_run_evidence_stage` / `_run_layout_stage` gain a keyword-only `registry: Registry` parameter (following the existing `_run_semantic_stage` style in the same module), `_ensure_analysis_stages` forwards it, and neither runner calls `load_registry()` anymore. The documented invariant: a caller that routes with an overriding registry **must** pass that registry's digest to `stage_config_inputs`.
10. **`rerender_workspace` does not take the argument.** It rewrites only the TRANSLATE/RENDER `make_stage_record` calls, and the configuration those two stages get from `stage_config_inputs` is `common + {targetLocale, sourceLocale, providerModel, providerEndpoint, terminologyFile}` and `{renderProfile, renderPolicy, latexTemplate}` — **no `capabilityRegistry`** — while it never touches the EVIDENCE/LAYOUT records. A registry override therefore cannot affect its cache-key correctness, and the parameter would be plumbing with zero observable difference.
11. **The bundled registry is untouched.** `data/capability-registry.toml` is unchanged and the primaries stay `mock` / `docling-sim` / `grobid-sim`. Changing a bundled primary is a deliberate replacement: prove it with an override file plus `just benchmark` first, then commit it separately.
12. **The benchmark uses the same entry point.** `tests/benchmark/run_benchmark.py` switches from `load_registry()` to `load_registry(load_parser_config().registry_path)`, so "prove an upgrade with an overriding registry" is one command (`PAPER_CAPABILITY_REGISTRY=<file> just benchmark`), and CI with no environment variable behaves exactly as before.
13. **`apps/api` / `apps/worker` gain no registry argument.** Both are pure argument wiring that reads no environment; the defaults of `run_pipeline` / `rerender_workspace` read the environment in-process, so setting `PAPER_CAPABILITY_REGISTRY` on the worker process covers both paths with no app change and no `JobRecord` field.
14. **Documentation split.** Operational guidance goes in `packages/python/pdf-pipeline/README.md` (how to set it, the precedence, the unchanged default, and benchmarking before changing a bundled primary); the current state of the cache keys and refusal semantics goes in [`docs/architecture/storage.md`](../../../../docs/architecture/storage.en.md); `run_pipeline` behavior goes in [`docs/architecture/pipeline.md`](../../../../docs/architecture/pipeline.en.md); grading and acceptance go in [`docs/development/m8.md`](../../../../docs/development/m8.en.md). One fact, one home, no copies.

## Alternatives considered

- **Write `migrate_workspace()` to convert old versions to new ones**: there is no old value to convert (every batch A–D manifest says `"0.1.0"` and the shape never changed), so the function body could only return its input. Writing it at the first real bump, with tests, is what actually keeps a migration path exercised.
- **`SUPPORTED_WORKSPACE_VERSIONS = (WORKSPACE_VERSION,)`**: bumping `WORKSPACE_VERSION` would silently drop the old version from the readable set, and the code would not show that "is the old version still readable?" is a decision. An explicit literal forces the bump author to face it.
- **Bump `WORKSPACE_VERSION` to mark this batch**: this batch changes no manifest field (only a code-side readable set and a config entry point), so a bump would reject every existing workspace for no reason. The rule batch C established is that extending the key material only reruns old workspaces once, which is the safe direction.
- **Fall back to the bundled registry when the override cannot be read**: a silent fallback is a silent parser swap — precisely the failure mode this batch exists to remove.
- **Cache the parsed override file**: the operator may edit it between two runs, and caching turns "the config changed" into "nothing changed". Only the bundled package data is worth caching.
- **Call `path.read_text()` inside `registry_fingerprint(path)` in addition to `registry_text(path)`**: an edit between the two reads would record a digest that does not match the artifacts produced with it — a silent cache hit. `resolve_registry` exists so a run reads exactly once.
- **Include the path in the fingerprint** (e.g. `sha256(path + content)`): the path is not a semantic input; two paths with identical content would produce two keys, turning a meaningless file rename into two stage reruns.
- **Add `--registry` to `apps/worker` as well**: the app layer should not own this parameter; the environment already covers both paths, and an argument adds a second configuration surface (and potentially a `JobRecord` field) to keep in sync.
- **Make `CapabilityRegistryError` not inherit `ValueError`**: that would slip past existing `pytest.raises(ValueError)` expectations and any caller catching registry problems as `ValueError`; inheriting is free compatibility.
- **Pass `registry` to the two runners positionally**: `_run_semantic_stage` in the same module already established the keyword-only style, and positional parameters would freeze the positional meaning of any future parameter.
- **Also rerun TRANSLATE/RENDER when the registry override changes**: those two stages do not consume the registry, so rerunning them would only obscure whether the key is correct.

## Consequences

- New `packages/python/pdf-pipeline/src/pdf_pipeline/config.py`: `REGISTRY_PATH_ENV`, `ParserConfig`, `load_parser_config`.
- `pdf_pipeline/capabilities.py`: new `CapabilityRegistryError`, `registry_text(path=None)`, `resolve_registry(path=None)`, `_bundled_registry()`; optional `path` on `load_registry` / `registry_fingerprint`; `_load_registry_impl` → `_parse_registry(text, *, source)`; `_validate(registry, *, source)`; a new `pathlib.Path` import.
- `pdf_pipeline/pipeline.py`: `stage_config_inputs(..., *, registry_digest=None)`; keyword-only `registry` on `_run_evidence_stage` / `_run_layout_stage`; `_ensure_analysis_stages(..., *, registry)`; `run_pipeline(..., pipeline_config=None)` resolving the registry before the workspace is built; the new `--registry` CLI flag; the import line changed to `registry_fingerprint, resolve_registry` (`load_registry` is no longer referenced in this module).
- `pdf_pipeline/workspace.py`: new `SUPPORTED_WORKSPACE_VERSIONS`; the `_load_existing` version check becomes a named set plus a guiding message; the module docstring's "migration belongs to M8 batch E" is replaced by the current state.
- `tests/benchmark/run_benchmark.py`: the registry comes from `load_parser_config()`.
- Tests: new `tests/test_parser_config.py` with 10 cases (default / env read, override taking effect with the fingerprint following it, content-not-path keying, fingerprint change after an edit, three refusal classes for missing / malformed / missing-internal-capability overrides, and the single-read `resolve_registry`); `test_workspace.py` replaces `test_unknown_workspace_version_rejected` with `test_supported_workspace_version_loads`, `test_unknown_workspace_version_refused_without_touching` (unchanged manifest bytes + no `.staging`), and `test_manifest_absent_directory_is_not_trusted`; `test_pipeline_resume.py`'s `test_registry_change_reruns_evidence_and_layout` (which patched `pipeline.registry_fingerprint` and would no longer be read after this refactor) is replaced by three tests going through the real configuration entry point: an override change → EVIDENCE and LAYOUT each run once with `probe.json`'s `routing[0].provider == "mineru"`, `degradations[0].provider == "mineru"`, and `workspace.json`'s `evidence.status == "degraded"` (the E/D interface connected); an identical-content copy → every runner at 0 calls; the `--registry` flag → routing follows the override. The three `test_specialist_isolation.py` cases migrate from patching `pipeline.load_registry` to a real override file (`_registry_override` writes the overlay as TOML), so batch D's isolation path is now driven through the real configuration entry point as well.
- Every call site is migrated: `pipeline`, `run_benchmark`, and `test_fake_specialists` / `test_fusion` / `test_routing` / `test_semantic` (which only use the default `load_registry()` and stay signature-compatible); no compatibility shims, no deprecated paths.
- Existing workspaces are unaffected: with no flag and no environment variable, the bundled registry's bytes are identical to today's, so `registry_fingerprint()` is unchanged, the cache keys are unchanged, and neither the golden file nor the benchmark baseline moves.
- Observed behavior: with no env and no flag, `just test-golden` and `just benchmark` match today's results; with `--registry` pointing at an override that sets `layout.region.primary` to `mineru`, `probe.json` shows `routing[0].provider == "mineru"`, `degradations[0].provider == "mineru"`, and `workspace.json` records EVIDENCE as `degraded` while the `ingest`/`physical` records keep identical bytes; `--registry /tmp/nope.toml` raises `CapabilityRegistryError` (message naming the path) before touching the workspace, with `workspace.json` bytes unchanged.
- Still unverified: real MinerU / Docling / GROBID tool output. This batch therefore does not change a bundled primary to a real tool, and does not fabricate dumps to make tests pass (`tests/fixtures/parser-dumps/provenance.json` stays `synthetic-contract`).
