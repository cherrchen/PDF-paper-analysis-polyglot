# Agent Note: Overleaf-Style Console Design System

Status: implemented

[中文](./2026-09-17-overleaf-console-design-system.md) | [English](./2026-09-17-overleaf-console-design-system.en.md)

## Problem

The visual language left by the M2 walking skeleton was bespoke: slate-blue borders (`#234f68` / `#afbec7` / `#9db6c2`), Charter serif headings, a `linear-gradient` center fold drawn across a 1560px "editorial" page, heavy drop shadows, monospace nearly everywhere, and an orange (`#e4572e`) selection color. The user supplied an Overleaf screenshot and asked the console to match its look: flat light-gray chrome, white surfaces, green primary actions, a sans-serif UI face, and monospace reserved for identifiers and paths.

Scope this round was explicitly set by the user to a **reskin only**: the DOM structure, the two-column `#panes` grid, the `#surface-tabs` row, and the right-hand **floating** `#surface-panels` drawer — including all of its geometry — stay put. The [2026-09-16 four-surface note](./2026-09-16-demo-console-surfaces.md)'s "the drawer consumes no PDF width" decision remains in force, so this round adds neither an Overleaf-style left rail nor a width-consuming drawer column. Exactly one control is added: the green primary `#open-upload` in the masthead, matching the position and color of Overleaf's Recompile/Share slot.

## Decision

1. **The palette is copied value for value from Overleaf's published stylesheet and has exactly one home.** Every scale and semantic token comes from `https://cdn.overleaf.com/stylesheets/main-style-476eb7ca577de65f3a7b.css` (fetched 2026-09-17) with the upstream token names (`--green-*` / `--neutral-*` / `--blue-*` / `--red-*` / `--yellow-*` plus the `--bg-light-*` / `--bg-accent-01` / `--content-*` / `--border-*` mappings), so the console chrome and the reference can be diffed line by line. That block is the only source of color in `viewer.css`: an `#rrggbb` literal may appear only inside `:root`, and everything else is `var(--…)` or an `rgb(… / …)` derived from those tokens (the two translucent overlays and the two shadows). The font stacks and `--radius` / `--shadow-*` / `--focus-ring` are console-local additions with no upstream counterpart.
2. **Layout geometry does not change.** The drawer keeps `top: 0; right: 0; bottom: 3.5rem; width: min(360px, 34vw)`, `z-index: 6`, and a `pointer-events: none` container; `.page-scroll` keeps `max-height: 72vh` and gains no padding, border, or margin; `.page-stage` keeps `overflow: hidden` and its canvas keeps `width: 100%; height: auto` with **exactly one** 1px border — fit-width and the `inset: 0` overlay alignment depend on those facts, so the reskin only changes color, radius, shadow, and type. `main` stays `min(1560px, 100%)` and merely loses its vertical padding and serif heading rules.
3. **A typographic division of labor.** UI text uses a system sans stack (no webfont download); monospace is reserved for identifiers, paths, page numbers, and geometry readouts (`#source-page` / `#target-page`, `#inspector-node-id`, `#inspector-anchors`, `#viewer-status`, select's path and the `updatedAt` lines). Inspector prose (`#inspector-source-text` / `#inspector-translation`) is sans at `--text-md`, because that text is the document being read, not an identifier.
4. **The masthead is a sticky white bar and the primary button shares the tab state machine.** `.masthead` becomes `grid-template-columns: auto 1fr auto` (`.brand-mark` swatch / `.brand-text` / `.masthead-actions`), and `#open-upload` does one thing — `SurfaceTabs.open("upload")` — so no open logic is duplicated and no `aria-controls` is added (the `#panel-upload` relationship already belongs to `#tab-upload`). `SurfaceTabs.open` is idempotent, so clicking the button while the panel is open does nothing; closing still goes through `#tab-upload`. At ≤ 840px the masthead collapses to `auto 1fr` with `.masthead-actions` on its own row, replacing the old `display: block` stack.
5. **Green means primary action and selection only.** The primary buttons (`#open-upload` / `#import-submit` / select's `.select-open` / history's `.history-open` / `#retranslate-button`) share one `:is(…)` rule; the id weight that `#import-submit` and `#retranslate-button` contribute outranks the secondary `.surface-panel button` / `.inspector-section button` styling, so no per-button rule is needed. The active tab (`aria-selected="true"`) and a pressed region (`aria-pressed="true"`) use the same green, and mapped regions are blue at rest and on hover — orange no longer means "selected".
6. **The two checkboxes are custom-drawn but still native `input`s.** `appearance: none` plus a green checked fill and a `box-shadow` focus ring; the box is `0.9rem` and is never `display: none`, `opacity: 0`, or zero-sized, because e2e drives `#inspector-toggle` and `#sync-scroll` with `check` / `uncheck` and the click point must land on the input itself.

## Alternatives considered

- **Adopt the full Overleaf shell with a left rail and width-consuming panels.** Structurally closest to the reference, but it directly supersedes the 2026-09-16 "the drawer consumes no PDF width" decision, and this round's goal was matching the look; the user chose reskin-only, so a left rail waits for a note of its own.
- **Keep the M2 slate-blue palette and change only type and shadows.** The smallest diff, but the point of the supplied screenshot was the green primary actions and light-gray chrome, so keeping the old colors would not execute the request.
- **Load Noto Sans / Inter as webfonts.** Would match Overleaf glyph for glyph at the cost of a new network dependency and a first-paint font swap, for a payoff that lives outside the screenshot; the system sans stack lets each platform use its own default UI face.
- **A dark theme or a `prefers-color-scheme` variant.** The reference is light-only, and splitting the token layer in two would force maintaining the region overlay colors and every translucent drawer fill twice; this round ships light only, with token names already shaped for a later variant.
- **Give `#open-upload` toggle semantics (open and close).** That would fork the state source away from `#tab-upload`; `SurfaceTabs` is the single source of state, so the button only forwards and a repeat click is a no-op.

## Consequences

- `apps/web/src/viewer.css`: `:root` (palette plus font/size/radius/shadow tokens), page chrome, panes and drawer, tabs and checkboxes, panels, and the Inspector are all rewritten; `box-shadow`, the `linear-gradient` center fold, the serif stacks, the `opacity` disabled tricks, and the orange selection color are gone; the geometry declarations of `.page-scroll` / `.page-stage` / `#surface-panels` are preserved verbatim.
- `apps/web/index.html`: the masthead block gains `.brand-mark` (inline SVG, `aria-hidden="true"`) and `#open-upload`; the rest of the file is byte-identical and every existing id is preserved.
- `apps/web/src/main.ts`: one click listener at the end of `init()` forwarding `#open-upload` to `tabs.open("upload")`.
- e2e: `tests/e2e/console-surfaces.spec.ts` asserts that clicking `#open-upload` makes `#panel-upload` visible with `#tab-upload` at `aria-selected="true"`, and that clicking `#tab-upload` closes it again.
- Vale vocabulary: `Noto` / `Overleaf` / `Overleaf's` / `monospace` / `reskin` / `select's` / `webfont` / `webfonts` are added to `.vale/styles/config/vocabularies/Paper/accept.txt`, because `Vale.Spelling` flagged every one of them as an error in the new docs, which fails `just docs`.
- Docs: the console's visual layer is recorded in [`reader.en.md`](../../../../docs/architecture/reader.en.md) (with its Chinese primary `reader.md`); every geometry fact in that section is preserved.
- Known costs: the system sans stack is not Overleaf's Noto Sans, so glyphs differ; `--green-20` / `--green-40` / `--neutral-05` / `--blue-10` / `--red-40` / `--yellow-*` have no consumer yet and are kept so the token block stays line-comparable with upstream.

This partially supersedes the visual language of the [2026-09-16 four-surface note](./2026-09-16-demo-console-surfaces.md): its decisions 1–8 (the four-surface split, the floating drawer, fit-width and ratio scrolling, the upload/select/status behavior, and the read/write boundaries) remain current. M6's jump and overlay contracts are in the [M6 note](../feature/2026-09-11-m6-bidirectional-reader.en.md).
