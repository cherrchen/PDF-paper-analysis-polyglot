# Agent Note: M8 batch C stage cache keys, invalidation propagation, and local rerun

Status: implemented

[中文](./2026-09-14-m8-batch-c-cache-keys-invalidation.md) | [English](./2026-09-14-m8-batch-c-cache-keys-invalidation.en.md)

## Problem

Batch A's stage state folded only "producer version + upstream artifact sha256" into `inputFingerprint`, and batch B's job layer holds no fingerprint at all. Changing the capability registry, a parser dump, or the translation config therefore never invalidated TRANSLATE/EVIDENCE: the workspace silently reused artifacts produced under the old configuration, while `docs/architecture/storage.md` explicitly assigned "stage invalidation on translation-config changes and cross-config cache keys" to batch C. The translation cache (`paper_llm.cache.TranslationCache`) did key on node/content/locale/model/endpoint/terminology/prompt/context, but carried no "key derivation rules version": after a change in what the key means, old rows were still read as hits. There was also no explicit local rerun entry point (rerunning one stage meant deleting the whole workspace), and a changed source PDF had exactly one outcome: an error.

Three acceptance criteria: retranslation does not rerun physical/layout/semantic; parser dumps, the registry, and source PDF bytes invalidate their dependents; the cache never falsely hits across configurations, versions, or source files.

## Decision

1. **Stage config folds into the existing `inputFingerprint`; no new manifest field, and `WORKSPACE_VERSION` stays `0.1.0`.** The material for `input_fingerprint(producer_version, inputs, config)` becomes `{producerVersion, inputs(sorted), config(sorted)}`; `WorkspaceManager` holds `stage_configs`, `commit_stage` no longer takes `inputFingerprint`, and computes it internally via `make_stage_record` (upstream records + stage config). Field names and manifest keys are unchanged. Rationale: extending the key material only reruns an old workspace once (the safe direction), whereas bumping `WORKSPACE_VERSION` would outright **reject** existing workspaces — and migration/rejection policy belongs to batch E, not here. A new field would additionally make "empty config" indistinguishable from "config not recorded" in the manifest, with the same migration question deferred to batch E.
2. **`pipeline.stage_config_inputs(config, source_bytes)` is the single source of truth**, returning the config mapping of each of the eight stages; both `run_pipeline` and `rerender_workspace` build their `WorkspaceManager` from it. Sharing one entry point is what makes the TRANSLATE/RENDER records that rerender writes agree with the next `run_pipeline` decision (otherwise every retranslation would cascade into a full rerun).
3. **Common inputs `schemaVersion` + `pipelineVersion`**: any stage-code or canonical-schema change invalidates every stage. The granularity is coarse (touching INDEX reruns INGEST too), but the direction is safe and no per-stage version constants must be maintained.
4. **The registry and parser dumps key on content digests, not version constants**: both are hand-edited data; a version constant would silently reuse output when someone edits the data and forgets to bump it. `registry_fingerprint()` and `template_fingerprint()` are imported into `pipeline` by name so tests can monkeypatch them.
5. **Parser dumps are resolved exactly as the adapters resolve them** (`resolve_dump_path(provider, fingerprint, env_path)`, the same function the real adapters call), and the value is the file's sha256; no dump records `"none"`, an unreadable dump records `"unreadable"`. Three literals are also keyed: `liveEnv:MINERU_CMD`, `liveEnv:DOCLING_CMD`, `liveEnv:GROBID_URL`. **All three real adapters participate regardless of routing**: routing needs a probe, and narrowing would misjudge which dump the stage actually reads; over-invalidating costs one rerun, a false hit goes silently stale.
6. **Translation config enters the key only where it changes artifact semantics**: `targetLocale`, `sourceLocale`, `providerModel`, `providerEndpoint`, terminology file bytes. **Excluded**: API key, `timeout_s`, `max_retries`, `cache_dir` — they do not change produced content, so keying them would only turn pointless config tweaks into reruns. `providerModel`/`providerEndpoint` come from `_provider_identity()`, the same source `_build_translation_provider` writes into `TranslationLayer.providerModel`, so the stage config and the layer identity cannot diverge.
7. **A changed source PDF keeps the default "explicit error" and gains an explicit opt-in**: `run_pipeline(..., accept_source_change=True)` / CLI `--accept-source-change` rebinds `sourceFingerprint` and drops every stage record (without deleting old artifact files on disk: the manifest is the only pointer, and each stage rerun overwrites its own declared paths). The default error is the batch A safety semantics; this batch does not change the default.
8. **Local rerun is an explicit entry point**: `run_pipeline(..., rerun_from=<stage>)` / CLI `--rerun-from <stage>` call `WorkspaceManager.invalidate_from(stage)` before running (in place, dropping that stage and every later record in `STAGE_ORDER`, then writing the manifest). It is exposed only through the `pdf_pipeline` Python API and CLI; `apps/`, the `JobRecord` shape, and the Job API are untouched.
9. **SEMANTIC clears `<ws>/resources/` before committing**: that stage's artifact set is `_directory_artifacts(resource_dir, "resources")`, i.e. "every file in the directory"; without the purge, leftovers from an earlier run or a different source would be registered as current output (and downstream stages would treat stale resources as fresh). `rerender_workspace` does not re-extract resources and is unaffected.
10. **Translation cache rows carry `cacheVersion` (`TRANSLATION_CACHE_VERSION`, currently `"1"`), and the constant is also the key-derivation version**: `_cache_key`'s payload gains `"version"`, `TranslationCache.__init__` skips rows whose version does not match (ignored, never migrated), and `put` writes the field. Not migrating is deliberate: key material across versions is not comparable, so a migration would be guesswork.
11. **Each key is computed once**: the RichText branch of `translate_document` computes `cache_key` and hands it to both `_translate_node` (cache read/write) and `_make_entry` (`TranslationEntry.cacheKey`); `_translate_table_content` computes one key per cell. `_make_entry` therefore shrinks to `(semantic_node_id, content, cache_key, confidence, provider_model)` — the caller supplies the key, so it no longer needs the context/kind/candidates parameters that existed only to compute one. A table node's node-level key is the whole-table content/config digest rather than a cache address (tables are cached per cell); that semantic lives in `_make_entry`'s docstring.

## Alternatives considered

- **Bump `WORKSPACE_VERSION` to `0.2.0`**: "the key material changed" does look like a version change, but the price is rejecting every existing workspace, and batch E owns migration/rejection policy; extending the key material is itself the safe direction (one extra rerun, never a false hit).
- **Add a `configFingerprint` manifest field**: the manifest would then contain two identically empty values — "empty config" and "old workspace, nothing recorded" — so the check would need a version or sentinel, deferring the same question to batch E; folding into the existing field makes an old workspace rerun everything naturally.
- **Per-stage code version constants**: eight constants to bump by hand on every stage-code edit, and a missed bump means silent staleness; a coarse `pipelineVersion` invalidation is enough.
- **A `REGISTRY_VERSION` constant for the registry**: the registry is a TOML data file and edits do not touch code, so only a content digest covers "edited the data, forgot the version".
- **Key only the adapters routing actually selects**: needs a probe (which depends on physical artifacts), binding key computation to a runtime decision — and a routing change can alter evidence content without changing which dumps are read.
- **Key api key / timeout / retries**: turns operational tweaks into full-chain reruns and leaks the key material into the manifest file.
- **Rebind automatically on a source change (no error)**: silently turns the workspace into another paper's artifact set; batch A already settled on an explicit error, and this batch only adds the opt-in.
- **Expose local rerun through the API only**: both CLI smoke tests and operators need it, and the Job API shape is out of scope for this batch.
- **Let `_make_entry` keep computing its own key (two computations)**: the two must stay equivalent forever, enforced only by convention; sharing one `cache_key` binds "the entry's key" to "the key that hit" in the type system.
- **Migrate cache rows across versions**: requires a converter per historical key material, while the cache is locally rebuildable derived data — ignoring old rows costs one provider call.

## Consequences

- `WorkspaceManager.commit_stage` no longer accepts `input_fingerprint`; the pipeline-private `_stage_inputs` is deleted and its "upstream not committed is fatal" guard moves into `WorkspaceManager._require_upstream_artifacts` (raising `WorkspaceError`, same message). New: `make_stage_record` (so the rerender transaction reuses the same key computation), `drop_stage_records`, `invalidate_from`, `_stage_config`.
- `open_or_create(source_bytes, *, accept_source_change=False)`: `_load_existing` now returns a source mismatch instead of raising it, leaving the caller to error or rebind.
- New in `pipeline`: `stage_config_inputs`, `_provider_identity`, `_file_digest`, `_parser_config_inputs`. New public functions: `capabilities.registry_fingerprint`, `render_latex.template_fingerprint`. New constant: `paper_llm.cache.TRANSLATION_CACHE_VERSION`.
- The CLI gains `--rerun-from` and `--accept-source-change`; `run_pipeline` gains two keyword arguments (`apps/` and the job layer are unchanged; their defaults preserve batch B behavior).
- An existing workspace reruns every stage once on the first run after this change (extended key material), then resumes on the new keys. Old translation cache rows are ignored once, then written under the new version.
- Batch A's landed "manifest write failure restores the in-memory record" semantics are unchanged (`commit_stage`'s previous/rollback branch is untouched); only the way the record is constructed changed.
- Verification: `test_workspace.py` 25 items, `test_pipeline_resume.py` 17 items, `test_rerender_workspace.py` 14 items, plus `test_cache.py` and `test_translation.py` all green; `just test-python`, `just check-fast`, `just test-golden` (`tests/golden/smoke/semantic.json` unchanged), and `just docs-fast` green; real `lualatex` CLI smoke: full run → `--rerun-from translate` (the first five stage records and artifact hashes byte-identical) → a second source PDF raising `WorkspaceSourceMismatchError` without the flag and rebinding/rerunning with `--accept-source-change`.
