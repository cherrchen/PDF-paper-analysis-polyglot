# Agent Note: M3 Layout Recovery Engine

Status: implemented

[中文](./2026-09-05-m3-layout-recovery-engine.md) | [English](./2026-09-05-m3-layout-recovery-engine.en.md)

## Problem

The M2 Walking Skeleton layout recovery was deliberately minimal: one band per page, naive middle-gap column detection, one region per line, a sort(y, x) linear reading flow, a caption heuristic inside the semantic layer doing geometric guessing, and no entry point for third-party parser evidence at all. M3 requires raising layout recovery from "recovered" to "reliably recovered page structure" and wiring up the first real consumption chain of the Evidence contract (`schemas/evidence/schema.json`).

## Decision

All eight phases are complete (Roadmap M3, Phase 3.1–3.8). Everything lives in `packages/python/pdf-pipeline/src/pdf_pipeline/` and is deterministic (identical input bytes produce byte-identical LayoutDocuments), with no LLM and no optimizer (Roadmap §4 Step 4).

1. **Evidence adapter boundary (3.1)**: new `pdf_pipeline.evidence` subpackage. The `EvidenceProvider` Protocol is the single entry point for parser output; `MockLayoutEvidenceProvider` is the deterministic baseline provider emulating a MinerU-like layout specialist, covering REGION/TABLE/FORMULA/HEADER/FOOTER candidates (each with a ProvenanceRecord). `normalize.py` performs label normalization (provider-native label → `LayoutLabel`, idempotent mapping), coordinate normalization (provider space → canonical page space, narrowed to bounding rects in v0.1), and cross-provider candidate matching keys. **Real MinerU is not installed**: heavy native dependencies require an Agent Note and the environment is not reproducible; a real adapter plugs into the same Protocol later (mock and real providers are equal citizens on the fusion side).
2. **Region Fusion (3.2)**: `pdf_pipeline.fusion`. Candidate matching requires geometric agreement (IoU ≥ 0.4 or containment ≥ 0.7) and label compatibility (`_LABEL_SIMILARITY` matrix); overlapping text previews boost the score. Labels are confidence-weighted votes with an agreement bonus, capped at 0.95 (layout recovery is never certain). Structured TABLE/FORMULA candidates match geometrically (label similarity skipped) and absorb the text blocks they cover (table rows); cell noise (paragraph candidates inside an absorbed region) is dropped; unmatched candidates become evidence-only regions (recall preservation). Every fusion output carries its reason (observability).
3. **Band/Column (3.3+3.4)**: `pdf_pipeline.page_structure` applies a recursive XY-cut: horizontal cuts first (full-width y-gaps ≥ 9pt), then vertical cuts (x-gaps ≥ 7pt spanning the strip's full height). **Structure detection runs before text blocking** — otherwise full-width lines (title/abstract) bridge left and right columns into one block. Single-line x-gaps (equation numbers, table cells) never span the strip height and can never split; x-islands narrower than 15% of the page (equation numbers) merge into their nearest neighbor; graphics (images + vector paths) are clustered into single items before column detection (TikZ arrows bridge boxes in unfavorable visit order, so consolidation runs to a fixpoint). Unbalanced columns (left column ends first) keep correct reading order naturally via the gutter cut. SPANNING/FULL_WIDTH classification needs document-level context: a second classification pass runs across pages (`reclassify_bands`) so a figure occupying a whole page is judged by the document's column layout.
4. **ReadingFlowGraph (3.5)**: `pdf_pipeline.reading_flow`. The primary order is driven by band/column structure: bands top-down, columns left-right; **within a column the order is still geometric (y, x)** (y quantized to 4pt so same-baseline items stay left-to-right). There is no document-wide `sort(y, x)`. Every ReadingEdge carries reason + confidence: SAME_COLUMN/NEXT_COLUMN, BEFORE/AFTER_SPANNING_BLOCK (band transitions), CAPTION_ASSOCIATION (direction-aware override from layout associations).
5. **Paragraph Continuation (3.6)**: for adjacent text regions, a source without terminal punctuation (after stripping closers) is the strong signal (+0.45); lowercase target start (+0.25) and a full-width source last line (+0.15, line broken at a column/page/figure boundary) assist; ≥ 0.6 becomes a CONTINUATION edge overriding the positional reason. Text pairs interrupted by a figure/table/formula get an extra CONTINUATION edge across the interruption. Semantic recovery (M4) merges paragraphs from this evidence.
6. **Caption Association (3.7)**: `pdf_pipeline.captions`. The layout layer scores caption prefix (`Figure N`/`Table N`), vertical distance (≤ 60pt, below-figure/above-table preferred), horizontal alignment, font size, and width ratio, then assigns greedily 1:1, emitting `LayoutGroup(FIGURE_BLOCK/TABLE_BLOCK)`. `semantic.py` now consumes these groups (a caption prefix conflicting with the target kind rejects the pair) instead of its own geometric heuristic. Captions may be wider than a centered figure (LaTeX convention); the hard cap is relaxed to 2.5×.
7. **Footnote Recovery (3.8)**: `pdf_pipeline.footnotes`. Footnote regions are page-bottom (≥ 72% page height) small-font (≤ 0.95× body) text blocks with a marker prefix (digit/symbol); unmarked small-font blocks directly below join the same flow. Footnotes form their own FOOTNOTE_FLOW chains and, together with header/footer furniture, **stay out of primaryFlow** (as the schema description states).
8. **Physical layer extension**: `physical.py` now extracts vector path objects (`FPDF_PAGEOBJ_PATH`, deliberately skipped in M2). `\rule`, TikZ drawings, and booktabs rules enter the PhysicalDocument; figure clustering filters decoration thinner than 2pt (rules) to avoid phantom FIGUREs. This is a required input for M3 band detection and a natural completion of the physical layer's "objective content" duty.
9. **Downstream adaptation**: `semantic.py` creates FOOTNOTE nodes for footnote regions (appended after the main flow) and records each node's source region in `attributes.layoutRegionId`; `pipeline.build_source_anchors` now pairs anchors **by identity** instead of positional enumeration; `render_composer.py` renders FOOTNOTE as a paragraph block (content completeness outranks layout fidelity, Roadmap §8). The pipeline emits `evidence.json` as a seventh canonical document.
10. **Benchmark (§6)**: `tests/fixtures/layout-truth/<fixture>.json` holds hand-derived ground truth for all 11 Tier-1 fixtures (reading-order snippets, caption pairs, footnote counts, `expectMultiColumn` / `expectSpanningBand` invariants); `tests/benchmark/test_layout_benchmark.py` + `pdf_pipeline.metrics` (token-prefix matching) compute Region Recall, pairwise ordering accuracy, and sequence accuracy. Gates: recall ≥ 0.9, pairwise ≥ 0.95, all sequences exact, caption/footnote assertions. **Two-column CI is carried by the lengthened synthetic fixtures**; BERT / Attention real-paper tests are `@pytest.mark.slow` and default CI does not download gitignored arXiv PDFs. Region precision is computed only over non-empty `primaryFlow` text regions; there is no invented high precision gate.

## Alternatives considered

- Installing real MinerU: multi-GB model downloads and native dependencies, violating the heavy-dependency Agent Note rule with an unreproducible environment; the mock provider shares the Protocol with real adapters, so the future integration cost is one class.
- Page-wide projection histogram for columns: single-line gaps (equation numbers) are indistinguishable from real gutters and produced 16-column bands; the XY-cut "gap spans full width/height" constraint eliminates single-line noise geometrically.
- Keeping M2 positional anchor pairing (i-th node ↔ i-th region): footnote nodes shift the alignment; `attributes.layoutRegionId` is the correct shape per the [source-mapping identity note](../../proposed/architecture/2026-09-03-source-mapping-identity-model.md).
- Keeping the golden SemanticDocument unchanged: smoke's merged paragraph blocks and fixed HEADING misclassification are intended behavior changes; per `docs/testing/golden.md` the diff was reviewed manually before updating.

## Consequences

- M3 Exit Gate met after the [review repairs](../bug-fix/2026-09-05-m3-review-repairs.en.md): band/column detection stable (lengthened Tier-1 fixtures assert `MULTI_COLUMN` / `SPANNING`), reading order on target (pairwise/sequence all green), caption association on target, cross-page/cross-column continuation usable (asserted on the cross-page-paragraph fixture), LayoutDocument passes schema validation and layer separation with no severe structural errors.
- New `pdf-pipeline` modules: `geometry`, `furniture`, `evidence/`, `fusion`, `page_structure`, `blocks`, `captions`, `footnotes`, `reading_flow`, `metrics`; `layout.py` became the orchestrator.
- Known limitations (intentional): (1) table cell structure depends on PDFium's merge behavior — when cells are pre-merged, only a whole-block TABLE region is recoverable and real TABLE_STRUCTURE needs MinerU; (2) math fragments enter the reading flow as line-level TEXT regions (M4 handles them via FORMULA evidence and semantic recovery); (3) region-precision ground truth is snippet-level (no full region-level annotation yet), so metrics emphasize recall and ordering, and precision waits for region-level labels; (4) `attributes.layoutRegionId` is an identity reference in the open attribute bag, carrying no geometry; (5) footnote reference evidence (body marks ↔ FootnoteRegion) is left to M4.
- No new third-party dependencies.
