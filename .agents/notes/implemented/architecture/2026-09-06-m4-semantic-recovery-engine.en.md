# Agent Note: M4 Semantic Recovery Engine landed

Status: implemented

[中文](./2026-09-06-m4-semantic-recovery-engine.md) | [English](./2026-09-06-m4-semantic-recovery-engine.en.md)

> The 2026-09-06 review reopened the M4 exit gate. This note keeps the original landing and rationale; first-round fixture and verification repairs live in the [M4 review-repairs note](../bug-fix/2026-09-06-m4-review-repairs.en.md); second-round correctness repairs live in the [M4 correctness-repairs note](../bug-fix/2026-09-06-m4-correctness-repairs.en.md). Clause 10 (“BIBLIOGRAPHY_ENTRY is translatable”) is partially superseded by [References are not translated (FR-CITE-004)](./2026-09-06-bibliography-not-translated.en.md): entries still render as paragraphs, but they do not enter the TranslationLayer.

## Problem

After M3 the layout layer is reliable (bands/columns/reading flow/captions/footnote regions), but `semantic.py` was still the M2 minimal engine: flat nodes one-per-region over `primaryFlow` (HEADING level hard-coded 1), consuming none of the M3 handoff — CONTINUATION edges, TABLE/FORMULA region text, or the TABLE_STRUCTURE / FORMULA / STRUCTURE / METADATA evidence candidates that `normalize.py` explicitly deferred to M4. Roadmap M4 (Phases 4.1–4.9) requires recovering paper structure from visual structure: paragraph merging, section hierarchy, table/equation/footnote/bibliography semantics, complete Source Mapping, and a SemanticValidator.

## Decision

All nine phases landed. The engine is a single-pass `_Recovery` plus seven `sem_*` stage modules (all under `packages/python/pdf-pipeline/src/pdf_pipeline/`, deterministic, no new third-party dependencies — continuing the M3 "no MinerU/GROBID" decision; real providers will flow through the same evidence path):

1. **Contract (preceding additive patch)**: `InlineMarkType` gained `FOOTNOTE_REFERENCE` (Roadmap 4.6 names FootnoteReference; reusing SUPERSCRIPT would drop the target semantics). Schema + fixture + `just generate` bindings + cross-language roundtrip changed atomically, version stays 0.1.0. Compatibility freeze took effect at the M2 exit gate; leaving MINOR unbumped is a recorded exception — see [M4 review repairs](../bug-fix/2026-09-06-m4-review-repairs.en.md). Later additive capabilities must bump MINOR.
2. **Input plumbing (4.1 prerequisite)**: `pipeline.region_lines_from` feeds per-physical-line text/rect/font size per region to the semantic layer; `region_texts_from` widened to TEXT/FOOTNOTE/TABLE/FORMULA. `recover_semantic_document(layout, texts, *, lines=None, evidence=None)` — both optional, heuristics degrade gracefully without them (golden tests stay deterministic without evidence).
3. **Paragraph merge (4.1)**: `sem_paragraphs`. Flow-adjacent body regions linked by CONTINUATION edges become ONE PARAGRAPH; `attributes.layoutRegionIds` (plural list, reading order) replaces M3's singular key; joins strip the `\x02` soft-break artifact and resolve line-final hyphenation. Merged confidence = min(0.75, weakest edge) with reason `paragraph merge: N regions`. `build_source_anchors` emits N-regions → 1 anchor (multi-fragment `SourceAnchor.fragments`, native since M1). Headings/captions/front matter/equation members never merge (label noise beats pattern precision).
4. **Section tree (4.2)**: `sem_sections` + the engine's `_open_section` stack. Heading level comes from the numbering pattern (`1.2.3` → level 3), not font size; unnumbered HEADING_LIKE lines must pass a prose-shape gate (4+-letter English words, no math operators), so years and math fragments never become headings. SECTION containers (`attributes={level,numbering,title}`) nest heading + following content until a level ≤ self; FRONT_MATTER is the root's first child: largest-font HEADING_LIKE line = title, `Abstract` line splits abstract-title/abstract body, ISO date = date, short capitalized lines = authors. `References`-style unnumbered headings stay level 1.
5. **Figure / Table / Equation (4.3–4.5)**: FIGURE carries `FigureContent.label` parsed from the bound caption prefix. TABLE prefers structured `TableCandidate` evidence (`sem_tables`), falling back to one row per physical line (PDFium merges cells) — never empty cells, reason observable. Math takes three routes: FORMULA regions or CONTINUATION-linked short-math runs (`sem_equations.display_groups`, `_strong_math` double gate) → EQUATION node; `(n)` regions absorbed into `EquationContent.number` (either side, incl. orphaned align exponents); inline `f(x)=x^2` gets `INLINE_EQUATION` marks via operator-anchored window expansion tolerant of PDFium's wide math spacing (`MULTI_COL UMN`-style flattened identifiers excluded). Prose-paragraphs containing inline math never become EQUATION nodes (4+-letter word vetoes display).
6. **Footnote (4.6)**: `sem_footnotes`. The footnote body's leading marker (digits or `*†‡§¶`) is a **string label** matched in body text; PDFium often inserts a space before superscripts (`footnote 1`), so letter-glue is not a precondition. Years / long digit runs stay excluded by the known-marker set. Emits `FOOTNOTE_OF` (footnote → host paragraph) plus a `FOOTNOTE_REFERENCE` mark. Empty FOOTNOTE regions still become nodes and report a `LAYOUT_REGION` WARNING. Same-page check keeps equal numbers across pages apart.
7. **Bibliography / Citation (4.7)**: `sem_bibliography`. `References` heading → BIBLIOGRAPHY container; `[n]`-prefixed paragraphs → BIBLIOGRAPHY_ENTRY (label attribute) with CONTINUATION fragments joined into the previous entry (reusing 4.1 merge semantics); in-text `[n]`/`[n,m]`/`[n-m]`/`[n–m]` → hyphen/en-dash closed ranges expand, then one CITATION mark + CITES relation per number; unresolved numbers stay in text and report a `CITATION_RESOLUTION` WARNING issue. GROBID / author-year citations are out of M4 scope.
8. **SemanticValidator (4.9)**: new `sem_validate.validate_semantic_recovery(semantic, layout, texts) -> Issue[]`: orphan/unreachable nodes (ERROR SECTION_STRUCTURE), heading level jumps in **document-tree order** (WARNING), FIGURE_CAPTION without CAPTION_OF (WARNING FIGURE_RECOVERY), TABLE_CAPTION without CAPTION_OF (WARNING TABLE_RECOVERY), content kinds missing `layoutRegionIds` or referencing unknown regions (ERROR SOURCE_MAPPING), CITATION/CITES target-kind mismatches (WARNING CITATION_RESOLUTION), other mark/relation target mismatches (WARNING SOURCE_MAPPING), primary-flow coverage (missing → WARNING, ERROR below 0.95 ratio; double-bound → ERROR). `run_pipeline` runs it after recovery and merges results into `semantic.issues`; recovery-time issues (duplicate entries, unresolved citations, empty tables) come from the engine. `test_semantic_validate.py` breaks one invariant per test and asserts detection fires.
9. **ID stability**: every node id derives from `stable_uuid(layout.id, "node", <semantic salt>)` (region id / "root" / "front-matter"); positional counters are gone, so adding/removing a node never perturbs others. The golden canonicalizer remaps `layoutRegionIds` element-wise; the M3 `\maketitle` author special-case is deleted — authors now land deterministically in FRONT_MATTER.
10. **Render fallback** (not M5 scope, anti content-loss): RenderComposer projects TABLE to row-major `cell | cell` paragraph blocks, EQUATION to `unicodeText|rawText (number)`, and BIBLIOGRAPHY_ENTRY is translatable (`paper_llm.TEXT_NODE_KINDS` widened). Container kinds carry no text and produce no block.
11. **Exit-gate fixture + benchmark**: new Tier-1 fixture `paper-anatomy` (title/author/date/abstract, two-level sections, figure+caption, table, numbered equation, footnote, thebibliography with in-text citations, two pages; no `\int` — the c1a3f75 PDFium-portability lesson) plus metadata YAML; all 12 `layout-truth/*.json` gained a `semantic` expectation block (kinds/minCounts/captionOf/footnotesLinked/citationsResolved/marks/equationNumbers/headingLevels/mergedParagraphNodes/multiFragmentAnchors/tableCellsMin/coverageMin/noErrors); `tests/benchmark/test_semantic_benchmark.py` asserts the whole M4 exit gate mechanically, including bundle-reference integrity and multi-fragment anchor counts.

## Alternatives considered

- **Zero schema change (reuse SUPERSCRIPT)**: viable, but FOOTNOTE_REFERENCE is the named Roadmap 4.6 contract and consumers need the distinction. MINOR was not bumped at the time; the freeze exception lives in the review-repairs note. This landing note does not rewrite the decision as “should have reused SUPERSCRIPT”.
- **Force FORMULA regions at the evidence layer**: attempted (formula threshold 0.25→0.15 kept as an improvement), yet Tier-1 math fragments still arrive as TEXT; the semantic-side CONTINUATION-chain + density + `_strong_math` double signal is the decisive path, evidence remains an enhancement.
- **GROBID-style STRUCTURE/METADATA evidence driving front matter/sections**: the mock provider does not emit them (normalize still skips those kinds); geometry+text patterns are deterministic enough on Tier-1, and a real GROBID adapter will use the same injection point (`evidence=` already consumed for TABLE/FORMULA).
- **Union-find closure for paragraph merging**: over-merges remote blocks across figure interruptions via M3's cross-interruption edges; the linear "flow-adjacent + edge present" chain preserves order.
- **Footnote markers via superscript font detection**: PDFium leaves FontRef.name empty and span merging dilutes font size; the text-shape rule (letter+digit with known marker set) has zero false positives across the 12 fixtures.
- **Keeping the old golden tree**: FRONT_MATTER/EQUATION/layoutRegionIds are intentional contract evolution; blessed again after human diff review per `docs/testing/golden.md` (this note is that review record).

## Consequences

- M4 exit gate met after [review repairs](../bug-fix/2026-09-06-m4-review-repairs.en.md): one paper recovers all ten structural element classes; `cross-page-paragraph` is a short-page single paragraph that paginates; semantic/layout benchmarks mechanically assert merge, Abstract, `1.1` nesting, and a cross-page CONTINUATION; `validate_semantic_recovery` reports zero ERROR issues on all 12 fixtures; bundle references intact; layer separation intact.
- New `pdf-pipeline` modules: `sem_paragraphs`, `sem_sections`, `sem_tables`, `sem_equations`, `sem_footnotes`, `sem_bibliography`, `sem_validate`; `semantic.py` becomes the orchestrator.
- Contract changes (additive, version still 0.1.0): `InlineMarkType` += `FOOTNOTE_REFERENCE` (recorded exception after the M2 freeze); semantic nodes carry `attributes.layoutRegionIds: list[str]` instead of `layoutRegionId: str` (open attribute bag, not a schema field; no consumer used the singular key).
- Known limits (deliberate): (1) the default mock does not emit TABLE_STRUCTURE, so the line fallback yields one column when PDFium merges cells; the structured path has a synthetic unit test, and true multi-column tables wait for an M7 specialist; (2) 1 Layout → N Semantic is not implemented — the cross-page contract is N Layout → 1 Semantic; (3) `FigureResource.embeddedImageIds` stays empty until a ResourceStore exists — PhysicalObjectID must not be written as ResourceID; (4) headings outside numbered / prose-shaped patterns (Appendix, Related Work) get no level without numbering or HEADING_LIKE shape; (5) citation parsing is numeric-bracket only — author-year text waits for GROBID in M7; (6) bare `_` requires a following digit to mark, which excludes flattened identifiers but may miss exotic `_`-only math (never loses content, only skips a mark); (7) `numbering` comes from text patterns, not layout-depth inference; (8) MathML and real figure PDF/SVG/raster assets wait for M5.
- No new third-party dependencies; `just generate` re-ran both language bindings with a clean diff.
